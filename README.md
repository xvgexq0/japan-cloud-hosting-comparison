# 日本云主机：先看线路、流量和计费，再选东京节点与套餐

找日本云主机，真正需要先解决的通常不是“买几核、几 GB 内存”，而是**你的用户到底在哪里、需要什么网络路径，以及流量用量会不会把月费之外的限制暴露出来**。

同样是东京机房，两台服务器的体验可能完全不同。对主要服务日本用户的站点，普通国际网络就可能已经够用；面向中国大陆用户的跨境网站、API、游戏或实时应用，则更应该先看回程线路，而不是只盯着 CPU 型号和端口上写着的 1Gbps。

这也是 DMIT 东京节点值得单独拆开的原因。DMIT 当前东京页面把网络分成 **Premium Network** 和 **Tier 1 Network** 两种路线：前者使用 CN2 GIA，面向中国大陆优化；后者强调亚太、北美和欧洲的国际互联，不提供同等级别的中国专项路由。东京节点当前使用 AMD EPYC 7003 系列处理器和全 NVMe SSD。

下面按“怎么选日本云主机”的真实购买顺序，把线路、套餐、价格、流量、优惠和容易忽略的限制一次讲清楚。

## 日本云主机到底该看什么

“日本”本身不是网络质量指标。

东京机房的地理位置确实适合连接日本国内、韩国、中国大陆、台湾以及东南亚等市场，但最终访问效果取决于运营商、上游线路、路由策略和具体目的地。DMIT 官方也明确提醒，东京到中国大陆的延迟数据属于参考值，实际结果会受到接入网络、路由和时间段影响。

因此，选日本云主机时，至少应该把需求拆成四个问题：

| 要看什么 | 真正影响什么 |
| --- | --- |
| 机房位置 | 用户到服务器的物理距离与区域覆盖 |
| 网络系列 | 中国大陆、亚太或全球访问时的路由质量 |
| 流量额度 | 网站、下载、视频、API 等业务能跑多大 |
| CPU / 内存 / SSD | 程序运行速度、并发能力和数据库性能 |

尤其要注意“带宽”和“流量额度”不是一回事。

套餐写着 1Gbps，并不等于一个月可以无限跑满 1Gbps。前者更接近端口峰值，后者才决定你的月度传输空间。DMIT 的文档还将流量计费分为双向计费和“单向最大值”两种模式，并说明超量后可以根据产品采用暂停、限速或其他处理方式，所以实际购买时应该直接看套餐的流量计费方式和超量规则。

## 东京 Premium 和 Tier 1：差别不只是价格

这是当前 DMIT 日本云主机最值得弄清楚的部分。

**Premium Network** 使用 CN2 GIA（AS23764），官方将它定位为面向中国大陆和东亚低延迟业务的网络。东京页面给出的参考数据是到中国大陆平均约 28ms、平均丢包低于 0.1%，但这只是官方参考测量，不代表所有地区、所有运营商和所有时段都会得到相同结果。

**Tier 1 Network** 则走国际 Tier 1 路由，官方公开描述重点是亚太、北美和欧洲的连接，并明确说它“不针对中国进行专项路由优化”。对于全球网站、备份、跨区域数据传输和不以中国大陆用户为主的应用，这种路线更符合它的产品定位。

所以可以把它理解成两个完全不同的购买逻辑：

> **中国大陆用户占比高：先看 Premium。**
> **日本、韩国、东南亚或欧美访问为主：Tier 1 更值得先比较价格和流量。**

这并不是说 Tier 1 在中国大陆一定不可用，而是它的产品定位本身就不是“中国优化线路”。反过来，也不要因为 Premium 有 CN2 GIA，就把它当成所有日本业务都必须购买的配置。你不需要的网络优化，最终也会反映在账单里。

## 哪个套餐适合建站、API 和跨境业务

如果你只是部署一个轻量个人网站、反向代理、监控服务或开发环境，1 vCore、1GB RAM 已经进入可考虑范围。真正应该根据业务决定的是流量，而不是为了“以后可能用到”直接买 4 核或 8 核。

例如：

**轻量建站和测试环境**：Tier 1 TINY $6.90/月是很低的入门门槛，1GB RAM、20GB SSD 和 2TB `Max (IN, OUT)` 流量。它更适合你已经判断“国际路由够用”的情况。

**中小型应用或 API 后端**：Tier 1 STARTER 到 MINI 的配置更宽裕。STARTER 变成 2GB RAM、40GB SSD、4TB 流量，MINI 再增加到 2 vCore、2GB RAM、60GB SSD、8TB 流量。

**跨境电商、实时应用、游戏或对网络抖动敏感的业务**：DMIT 官方把 Premium 的推荐场景直接写到了中国大陆网站和应用、在线游戏、直播以及跨境电商和支付平台。这个定位比“日本机房=低延迟”这种宽泛说法更有参考价值。

## 日本云主机为什么不能只看 CPU 和内存

很多主机对比表最吸引眼球的是“4 核、16GB、10Gbps”，但对于跨境部署而言，这种排序经常把真正决定体验的因素放到了最后。

假设网站用户主要在中国大陆，你把应用部署到东京之后，数据库、API、网页资源都要跨境传输。此时网络路径的稳定程度会直接影响打开速度和请求延迟。DMIT 当前东京页面甚至单独把 Premium 的 CN2 GIA 路由和 Tier 1 国际线路拆成两个系列，就是因为这两种使用场景本来就不同。

反过来，如果用户主要在日本国内，或者业务重点是日本、韩国、东南亚与美国之间的数据交换，那么把预算大量花在面向中国大陆的专项线路上，可能并没有必要。

这也是日本云主机选型最容易出现的一个误区：**把“线路贵”误认为“服务器更强”。**

DMIT 东京当前的硬件平台是 AMD EPYC 7003 + NVMe，Premium 和 Tier 1 的核心差异之一来自网络系列，而不是简单的“贵的套餐 CPU 更高级”。

## 流量超量怎么办

这是购买日本云主机时很容易被忽略的一项。

DMIT 当前文档提供三种流量超量处理模式：超量后暂停、超量后限速，以及不限制。具体产品采用哪一种，需要看对应服务的实际设置。文档还说明，大多数常规套餐支持付费重置流量，费用按照该实例的月费用折算；流量额度通常会在下一个周期自动恢复。

这意味着你不能仅凭“每月 2TB”就判断风险有多大。

一个静态网站每个月消耗几百 GB，和一个每天跑大量镜像、视频、备份或文件分发任务的服务器，虽然可以购买同一套餐，但流量超量概率完全不同。

如果你的项目具有明显的突发流量，建议在部署之前先估算：

`月访问量 × 单次平均传输量 + 备份/同步流量 + 系统更新流量`

不用追求精确到个位数，但至少要知道自己属于“几百 GB/月”还是“几 TB/月”的量级。

**网络是否适合你的运营商？**

**IP 是否满足你的业务要求？**

**流量超量后怎么处理？**

## 下单前，建议自己做一次线路验收

日本云主机尤其适合先测后长期使用。

DMIT 东京页面提供的是正式生产套餐，但官方自己的延迟数据也强调“实际延迟因接入网络、路由和时间而变化”。换句话说，一张网页上的平均值不能代替你自己的线路测试。

可以在正式部署前做三组简单检查：

1. 从目标地区测试 IPv4 和 IPv6 的延迟、抖动、丢包。
2. 用 `mtr` 或 `traceroute` 看关键路径经过哪些 AS。
3. 在晚间高峰再次测试，而不是只在白天测一次。

如果你的用户主要来自中国大陆，还应该分别测试电信、联通、移动，不要只拿某一个宽带运营商的结果代表“三网”。

对于主要面向日本本土用户的项目，则应该反过来重点测试日本本地不同网络和主要云服务、API 的访问情况。

## FAQ：日本云主机购买前最容易问的几个问题

### 日本云主机和日本 VPS 有区别吗？

在很多实际购买场景里，两者都可能指基于虚拟化技术的云服务器。具体还是要看产品本身提供的是 VPS、Cloud Instance 还是其他虚拟机形态。

DMIT 当前对应的是 Cloud Instance，其东京节点使用 KVM 虚拟机与 AMD EPYC 7003 平台。

### DMIT 东京一定要买 Premium 吗？

不一定。

如果你的业务主要服务中国大陆用户，Premium 的 CN2 GIA 路由才是这个系列最核心的购买理由；如果你的需求主要是日本、亚太或全球国际互联，而且不依赖中国专项路由，Tier 1 的产品定位可能更贴合需求。

### $6.90 的 TINY 能不能建网站？

可以作为轻量项目的起点，但“能不能”取决于网站的软件栈、访问量、数据库大小和缓存策略。

它只有 1 vCore、1GB RAM、20GB SSD。对于静态网站、轻量应用或测试环境可能足够；如果是较重的 PHP 应用、大型数据库或多个容器同时运行，内存往往比“日本机房”这个标签更早成为瓶颈。

### 流量用完后服务器会不会直接没了？

不应该这样理解。

DMIT 文档列出了暂停、限速和不限流量等不同超量处理方式，具体行为取决于实例产品。多数常规套餐还支持付费重置，或者等待下一个流量周期自动恢复。

### 能不能先买，再升级？

同一系列的实例支持升级到商店中有售的更高配置，但新套餐的存储容量不能低于原套餐；目前不支持降级。

这也是不建议一开始为了“以后可能会用到”买超大套餐的原因。先按照真实负载起步，再升级，通常更容易控制成本。

## 最后怎么选
